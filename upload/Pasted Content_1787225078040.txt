==================================================
IMPORTANT ARCHITECTURE
==================================================

The SVG frontend itself is hosted independently through GitHub/jsDelivr.

Static files such as:

- SVG wrapper
- JavaScript
- CSS
- icons/images
- Scramjet static assets
- WASM
- service worker files
- chunks

can be distributed entirely through GitHub/jsDelivr.

HOWEVER:

The SVG app is NOT backend-independent.

svg-client/runtime-bridge.ts currently hardcodes:

export const SYNNICAL_BACKEND_ORIGIN =
  "https://synnical.co.uk"

Relative /api/* requests are rewritten to that backend.

Therefore:

SVG frontend changes can be pushed ONLY to synnical-svg without updating the normal synnical.co.uk frontend.

BUT backend-dependent changes still require the backend at synnical.co.uk, or another replacement backend, to be updated.

Examples of SVG-only changes:

- UI
- layouts
- buttons
- animations
- desktop behaviour
- visual changes
- client-side components
- static assets
- frontend error handling

These can be updated only in synnical-svg.

Examples that REQUIRE backend changes too:

- new API endpoints
- changed API response formats
- database/schema changes
- authentication logic
- Socket.IO events
- server-side profile data
- shop/credit logic
- moderation actions
- Games/Stratus backend changes
- Wisp server changes
- server-side SynnFlix logic

Do NOT let SVG frontend code assume a backend feature exists unless the deployed backend actually contains it.

11. STRATUS / GAMES FAILURE THAT WAS JUST FIXED
==================================================

Games was seriously broken.

Symptoms included:

- Games section not loading correctly
- unknown errors
- raw HTML displayed in UI
- responses such as:

  <!DOCTYPE html><html...

Root cause was proven.

Production was missing:

/var/www/synnical/stratus/sites.json

server.ts enables Stratus by default, but intentionally disables the cloud gaming API when sites.json is missing.

Because Stratus was disabled:

/api/games/cloud/*

fell through into Next.js.

Next.js then returned its HTML 404 page.

Games client displayed that HTML.

Timeline proved this.

Stratus worked through:

2026-08-18 08:29 UTC

and started reporting:

Stratus cloud-gaming API: DISABLED

from:

2026-08-18 15:31 UTC

The config was lost during a deployment.

A real known-good config was recovered.

Known-good SHA-256:

22a62889c349087b0d6d6f4449701b85c7892d3db5ac9a78d7fd5f11abefaeba

It contained:

1 configured site

and a valid API key.

Instead of putting private config back inside the deployment directory, it was moved to:

/var/lib/synnical/stratus/sites.json

Production .env now points:

STRATUS_SITES_PATH=/var/lib/synnical/stratus/sites.json

This prevents a future source deployment from deleting the provider configuration.

After repair:

Stratus mounted at /api/games

Stratus cloud-gaming API mounted at:

/api/games/cloud/v1/*

Wisp remained mounted.

Direct catalog test:

HTTP 200
application/json
225 games

Public catalog:

HTTP 200
application/json
225 games

Invalid queue request:

HTTP 401
JSON
NOT HTML

Therefore the routing-layer raw HTML bug is currently repaired.
